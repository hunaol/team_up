1. 背景与目标

学生参加学科竞赛、创新创业比赛时，常常面临两个问题：自己想参赛但凑不齐队伍；已有队伍但缺少特定方向的成员。目前主要靠班级群、朋友圈零散传播，信息沉得快、覆盖窄，且无法区分“找队友”和“找队伍”两类诉求。

本平台提供一个集中的招募信息板：学生用学号和姓名注册后，可以发布“找队友”或“找队伍”的招募帖并留下联系方式，也可以浏览他人的招募帖，通过帖子中留存的联系方式自行线下联系，完成组队。

可观察的完成标准：用户从注册到成功发布一条带联系方式的招募帖，全程无需他人协助；其他用户无需询问即可在列表中找到该帖并看到联系方式。

同时提供管理平台，供管理员维护用户与帖子秩序（停用违规用户、下架违规帖子），保证信息板可持续使用。

2. 产品范围

优先级内容
P0 用户端：学号+姓名注册登录；发布“找队友/找队伍”招募帖（必留联系方式）；浏览与筛选帖子列表、关键词搜索；查看帖子详情（联系方式仅登录可见）；管理本人帖子（关闭、删除）。
管理平台：管理员账号登录；数据概览；用户管理（查询、停用/启用）；帖子管理（筛选、搜索、下架）。
P1 已实现 帖子收藏、浏览量统计——已在 v1.2 实现（规则见 7.5）。
暂不做 站内私信/聊天（联系通过帖子中留存的联系方式线下完成）；招募信息的发布审核（先发布后管理，违规由管理员下架）；简历/技能标签匹配；文件与图片上传。

3. 角色与数据模型

3.1 角色

角色说明进入方式
游客未登录访问者直接访问，仅可浏览帖子
注册用户以学号+姓名注册的学生注册后可发布与管理本人帖子
管理员平台运营维护人员使用预置管理员账号登录管理平台

3.2 核心对象

对象字段规则
用户 学号、姓名、注册时间、账号状态 学号全局唯一；账号状态：正常 / 停用
招募帖 类型（找队友/找队伍）、赛事名称、描述、需求人数、联系方式、发布者姓名、发布时间、状态 类型、赛事名称、描述、联系方式为必填；联系方式以明文展示；帖子状态见 3.3

3.3 帖子状态机

状态含义可转换到触发者
招募中正常展示，可被联系已招满、已下架、删除发布者 / 管理员
已招满发布者确认组队完成，仍展示但提示已满已下架、删除发布者 / 管理员
已下架管理员下架，前台列表与详情不可见；发布者在“我的发布”中可见该状态—（终态）管理员

删除：发布者可删除本人“招募中/已招满”的帖子，删除后数据移除、不可恢复。过期：发布超过 30 天的帖子自动视为“已过期”（读取时计算，规则见 7.4）。

4. 核心流程

发布方：注册（学号+姓名）→ 登录 → 填写招募帖（选类型、赛事、描述、联系方式）→ 提交成功 → 帖子进入列表（招募中）→ 组队完成后关闭（已招满）或删除。

寻找方：进入平台 → 浏览/筛选帖子列表（可先不登录）→ 点开详情查看联系方式 → 通过联系方式线下联系 → 达成组队。

管理员：登录管理平台 → 查看数据概览 → 按需处理用户（停用/启用）或帖子（下架）。

5. 功能需求 · 用户端

FR-01 注册与登录 P0

目的：以最低门槛建立可信的校内身份（学号唯一），支撑发布与帖子归属。

字段规则
学号必填，全局唯一，5–20 位数字或字母组合
姓名必填，2–20 个字符

处理规则：

① 注册：校验格式 → 校验学号未被注册 → 创建账号并自动登录；学号已存在时提示“该学号已注册”。
② 登录：输入学号+姓名，与已有账号完全匹配则登录成功；否则提示“学号或姓名不正确”（不区分具体原因）。
③ 登录后保持会话，刷新页面不掉线；可主动退出登录。

[假设，待确认] 登录不设密码，凭“学号+姓名”匹配即可（校园轻量场景）。如需密码或验证码，请在评审时提出。
[假设，待确认] 被停用的用户尝试登录时提示“账号已被停用，请联系管理员”。

FR-02 发布招募帖 P0

目的：让注册用户快速发布一条可被联系的招募信息。

触发条件：已登录用户点击“发布招募”。

字段必填规则
类型是单选：找队友（我组队缺人）/ 找队伍（我想加入队伍）
赛事名称是2–50 字符，如“全国大学生数学建模竞赛”
描述是10–500 字符，说明需求、要求、时间安排等
需求人数否1–99 的整数，默认不填（“找队伍”类型可不填）
联系方式是先选择类型（微信 / QQ / 手机号），再填写对应号码：QQ 为 5–12 位数字，手机号为 11 位（1 开头），微信号为 5–100 字符；仅登录用户可见

处理规则：提交时逐项校验，不通过则在对应字段下提示；通过后帖子以“招募中”状态入库，发布者自动署名（姓名），跳转/提示发布成功。

异常：未登录访问发布页时引导先登录；被停用用户提交时提示“账号已被停用，无法发布”。

FR-03 浏览与搜索帖子列表 P0

目的：让寻找方快速找到匹配的招募信息（参照招聘网站职位列表页“筛选 + 搜索”模式）。

处理规则：

① 列表默认展示全部“招募中/已招满”帖子，按发布时间倒序；“已下架”“已过期”帖子不展示。
② 顶部筛选：全部 / 找队友 / 找队伍；与搜索框可同时生效（AND 组合）。
③ 搜索框：按关键词对“赛事名称 + 描述”做 OR 匹配。
④ 列表项展示：类型标签、赛事名称、描述摘要（前 40 字）、发布者姓名、相对发布时间（24 小时内显示“X 分钟前 / X 小时前”，超过则显示日期）、状态。
⑤ 无数据时展示空状态文案：“暂无招募信息，来发布第一条吧”。
⑥ 页面适配移动端（响应式布局）。

[已确认] 游客可浏览列表与详情，但不可查看联系方式、不可发布（见 FR-04）。

FR-04 帖子详情与联系 P0

处理规则：

① 点击列表项进入详情，展示全部字段。
② 联系方式仅登录用户可见：游客看到遮罩占位与“登录后可查看联系方式”按钮；点击跳转登录，登录成功后自动返回当前详情页并展示联系方式（参照招聘网站“登录后可投递/查看”的门槛模式）。
③ “已招满”帖子在详情顶部提示“该招募已完成，仅供参考”。
④ 平台不提供站内聊天，联系在线下完成。
⑤ 一键复制：联系方式旁提供“复制”按钮，点击后写入剪贴板并提示“已复制到剪贴板”（参照招聘网站复制联系方式的通用交互）。
⑥ 类型标识：详情页联系方式标题明确标注类型（如“联系方式（微信 · 登录用户可见）”），游客遮罩区同样提示类型，避免不知道该加哪个。

交互演示 · FR-03 / FR-04（点击帖子展开详情；点右侧按钮切换身份，体验联系方式遮罩）

FR-05 我的发布 P0

目的：发布者管理自己帖子的生命周期。

处理规则：

① “我的发布”仅展示当前用户本人的帖子（含“已下架”状态，便于知晓处理结果）。
② 关闭招募：仅“招募中”可操作，确认后状态变为“已招满”。
③ 删除：需二次确认，文案“删除后不可恢复，确认删除？”；确认后帖子移除。
④ 被下架的帖子不可再操作，仅展示“已下架”状态。
⑤ 超过有效期的帖子展示“已过期”状态，不可再操作（规则见 7.4）。

6. 功能需求 · 管理平台

FR-06 管理员登录 P0

管理员使用账号+密码登录独立的后台入口；登录成功后进入数据概览页，未登录访问任何后台页面均跳转登录页。

[假设，待确认] 系统预置一个管理员账号（如 admin / admin123），首期不做多管理员与权限分级。

FR-07 数据概览 P0

展示平台核心计数，辅助管理员掌握运行情况：注册用户数、帖子总数、“找队友”帖数、“找队伍”帖数、“招募中”帖数。

FR-08 用户管理 P0

目的：处置冒用学号、发布违规内容等异常用户。

处理规则：

① 用户列表：学号、姓名、注册时间、发布帖数、账号状态；支持按学号/姓名搜索。
② 停用：二次确认后账号变为“停用”。被停用用户无法登录、无法发布；其已发布的帖子保持展示（帖子本身无违规时），如需移除走帖子管理下架。
③ 启用：恢复为正常，用户可重新登录。

FR-09 帖子管理 P0

目的：下架虚假、违规或重复的招募帖。

处理规则：

① 帖子列表：类型、赛事名称、发布者姓名、发布时间、状态；支持按类型/状态筛选，按赛事名称关键词搜索（覆盖 P1 搜索能力）。
② 下架：仅“招募中/已招满”可操作；二次确认后状态变为“已下架”，前台列表与详情立即不可见；发布者在“我的发布”中可见“已下架”。
③ 已下架为终态，不提供恢复上架（如需恢复，由用户重新发布）。

7. 公共规则与权限

7.1 权限矩阵

操作游客注册用户管理员
浏览帖子列表 / 详情✔✔—（在后台帖子管理中查看）
查看联系方式✘（遮罩展示，引导登录）✔✔（后台可见）
发布招募帖✘（引导登录）✔（账号正常时）—

下架帖子✘✘✔

7.2 通用校验与反馈

场景行为
表单校验失败阻断提交，在对应字段下给出具体原因（如“联系方式为必填项”）
破坏性操作（删除帖子、停用用户、下架帖子）必须二次确认，文案说明不可恢复/影响范围
接口异常 / 网络失败全局提示“操作失败，请稍后重试”，不丢失用户已填写内容
列表为空展示空状态文案，发布入口场景附“去发布”引导

7.3 隐私与安全说明

① 联系方式为发布者自愿提供，仅对登录用户明文展示，降低游客与爬虫抓取带来的隐私风险；发布表单需明示“登录用户可见”。
② 学号不对外展示：列表与详情仅展示发布者姓名，学号仅用于账号唯一性与后台管理。
③ 管理员账号密码需加密存储（具体方案属技术设计范畴）。

7.4 帖子有效期

帖子自发布起 30 天内有效（读取时计算，无需定时任务）：超过 30 天自动视为“已过期”——前台默认列表不展示；发布者“我的发布”与管理平台帖子管理中展示“已过期”状态；过期帖子不可再操作。目的是保持信息板时效性，参照招聘网站职位有效期机制。

7.5 收藏与浏览量（v1.2 新增）

① 收藏：登录用户可在列表卡片、详情页收藏/取消收藏，状态实时同步；“我的收藏”页按收藏时间倒序展示仍然可见的帖子（已下架/已过期的自动不展示）。游客点击收藏时引导登录。
② 浏览量：帖子详情每被打开一次计数加 1，在列表、详情页与管理平台帖子管理中展示，用于反映招募热度。
